# Getting Started

This guide is for first-time users. It explains how to clone the project, prepare the environment, handle models, build images, start services, and verify the platform.

If the target machine has no network access, skip this guide and use [Offline Deployment](../deployment/offline-deploy.md).

## Clone the Project

```bash
git clone https://github.com/332560915/funasr-deploy-kit.git
cd funasr-deploy-kit
```

If you receive the project as a source archive, extract it and enter the project root directory.

## Requirements

- Linux server, or a local Linux/macOS environment that can run Docker.
- Docker is installed.
- Docker Compose v2 is installed and available as `docker compose`.
- Image build requires access to Docker image registries.
- If models are not prepared in advance, the first FunASR Server startup requires access to model download sources.

Check commands:

```bash
docker --version
docker compose version
```

## Models

Default models:

```text
ASR  model:       damo/speech_paraformer-large-vad-punc_asr_nat-zh-cn-16k-common-vocab8404-onnx
VAD  model:       damo/speech_fsmn_vad_zh-cn-16k-common-onnx
PUNC model:       damo/punc_ct-transformer_cn-en-common-vocab471067-large-onnx
ITN  model:       thuduj12/fst_itn_zh
LM   language model: damo/speech_ngram_lm_zh-cn-ai-wesp-fst
```

Model cache directory:

```text
deploy/models
```

Container mount path:

```text
/workspace/models
```

### Option 1: Download Models Online

If `deploy/models` is empty but the server can access the network, FunASR Server downloads models according to the model IDs in `deploy/config/start-funasr.sh` and caches them under `deploy/models`.

This option is suitable for quick evaluation and development. The first startup may be slow depending on network speed and model download speed.

### Option 2: Prepare Local Models

If models have already been downloaded, place them under `deploy/models`. Offline environments must use this option or use the offline runtime package generated by this project.

When you need to pin local model paths, change the model variables in `deploy/config/start-funasr.sh`, for example:

```bash
FUNASR_ASR_MODEL=/workspace/models/damo/speech_paraformer-large-vad-punc_asr_nat-zh-cn-16k-common-vocab8404-onnx
FUNASR_VAD_MODEL=/workspace/models/damo/speech_fsmn_vad_zh-cn-16k-common-onnx
FUNASR_PUNC_MODEL=/workspace/models/damo/punc_ct-transformer_cn-en-common-vocab471067-large-onnx
FUNASR_ITN_MODEL=/workspace/models/thuduj12/fst_itn_zh
FUNASR_LM_MODEL=/workspace/models/damo/speech_ngram_lm_zh-cn-ai-wesp-fst
```

For model parameter details, see [Configuration](../deployment/configuration.md).

## Prepare Configuration

Copy the HTTP API configuration example:

```bash
cp deploy/config/http-api.env.example deploy/config/http-api.env
```

For quick evaluation, the default configuration is usually enough. Important values:

```env
FUNASR_WS_URL=ws://funasr-server:10095
UPLOAD_TEMP_DIR=/app/tmp
LOG_FILE=/app/logs/http-api.log
MAX_UPLOAD_SIZE=31457280
```

To adjust ports, upload size, concurrency, or timeouts, see [Configuration](../deployment/configuration.md).

## Build Images

Recommended script:

```bash
bash scripts/build.sh
```

Equivalent command:

```bash
docker compose -f deploy/docker-compose.yml build
```

## Start Services

```bash
docker compose -f deploy/docker-compose.yml up -d
```

Check container status:

```bash
docker compose -f deploy/docker-compose.yml ps
```

View startup logs:

```bash
docker compose -f deploy/docker-compose.yml logs -f funasr-server
docker compose -f deploy/docker-compose.yml logs -f http-api
```

## Verify

Health check:

```bash
curl http://127.0.0.1:18000/health
```

Open Swagger UI in a browser:

```text
http://127.0.0.1:18000/docs
```

If deployed on a server, replace `127.0.0.1` with the server IP.

Upload an audio or video file:

```bash
curl -F "file=@/path/to/audio-or-video.mp4" http://127.0.0.1:18000/api/v1/asr
```

The default upload limit for the synchronous API is 30MB. Use short audio or a small file for the first verification.
