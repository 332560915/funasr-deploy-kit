# 下一版本规划

本文记录下一版本的功能规划，不代表当前版本已经实现。

## 大文件识别

当前 `POST /api/v1/asr` 是同步接口，适合短音频、功能验证和 Swagger 联调。大文件或长音频会导致 HTTP 请求长时间占用，也容易受到客户端、反向代理或服务端超时影响。

下一版本计划新增异步任务接口：

```text
POST /api/v1/asr/jobs
GET  /api/v1/asr/jobs/{job_id}
GET  /api/v1/asr/jobs/{job_id}/result
```

建议状态：

```text
pending
running
succeeded
failed
expired
```

## 任务持久化

大文件识别不建议只依赖内存状态。下一版本建议引入轻量持久化：

- 使用 SQLite 保存任务状态、文件路径、识别结果、错误信息和时间戳。
- 上传文件保存到任务目录，例如 `/app/tmp/jobs/{job_id}`。
- 后台 worker 从待处理任务中取任务并执行识别。
- 服务重启后可以恢复未完成任务或标记为失败。

## 缓存设计

这里的“缓存”建议拆成两类：

### 结果缓存

对上传文件计算摘要，例如 SHA-256。若相同文件已经识别成功且结果未过期，可以直接返回已有结果，避免重复识别。

适用场景：

- 用户重复上传同一文件。
- 调用方失败重试。
- Swagger 或测试环境反复验证同一音频。

### 任务状态缓存

任务状态需要可靠保存，不建议只放内存。可以用 SQLite 作为任务状态存储；如果后续需要多实例部署，再考虑 Redis。

## 并发控制

FunASR offline 识别通常比较耗资源。下一版本建议限制后台识别并发：

```text
ASR_WORKER_CONCURRENCY=1
```

后续可根据机器资源调整为 2 或更高。

## 清理策略

需要定期清理：

- 已完成任务的临时上传文件。
- 过期任务记录。
- 过期结果缓存。

建议增加配置：

```env
JOB_RETENTION_HOURS=24
RESULT_CACHE_TTL_HOURS=168
```

## 当前建议

- 当前版本同步接口限制为 30MB。
- 大文件、长音频和生产批量转写走下一版本异步任务方案。
- 下一版本优先实现 SQLite 任务持久化和结果缓存，不急于引入 Redis/Celery。
